# V4 积分与 LoveDiary

积分和 LoveDiary 均从独立导航进入；主页不展示积分卡片。手机底部导航可横向滑动。

## 日常使用

- 在积分页的加分 / 扣分标签中创建项目，填写名称、原因与分值。以后点击项目、选择积分归属人并确认即可执行；取消不会记账。项目可编辑或停用。
- 奖励标签默认提供 LoveDiary，也可以创建自定义奖励。兑换使用当前使用者的积分，余额不足时不执行。
- LoveDiary 可编写和编辑自己的日记，每篇独立设置积分价格。对方兑换前只能在页面看到标题、日期、价格；确认兑换后永久解锁，不重复收费。作者修改正文后，已解锁者可以阅读更新内容。
- 积分页展示双方独立余额和流水。流水保留当时的原因、实际分值、操作者和来源；普通扣分最低扣到 0，不形成欠分。

## 好习惯

- 编辑好习惯时设置完成加分、未完成扣分和是否启用，0 分表示不生成对应积分项目。停用的习惯保留在习惯页，可以重新启用。
- 有积分设置的习惯由打卡自动执行，积分页只展示关联规则，不提供重复手动计分按钮。
- 统一按北京时间划分日期；次日打开、同步或前台定时检查时补结算未完成的启用习惯。应用关闭时没有服务器定时任务。
- 配置变更前先结清过去日期，过去流水不重算。当天已完成打卡保留原奖励金额；撤回再打卡也不会因改分值获得额外积分。
- 取消当天打卡须撤回原奖励；如果积分已消费且余额不足以撤回，则提示补足积分后再取消。停用不撤销已获得积分。
- 旧习惯首次保存积分设置时迁入 V4，当天已存在的打卡保留且不补发积分，更早的历史继续可见。迁入后不能修改归属人，可为另一人新建习惯。

## 保存与兼容

新数据统一存放在私有数据仓库的 `couple-data/points/shared.json`，包含项目、V4 习惯配置与打卡、日记、流水及结算进度。一次习惯打卡或奖励兑换在单次带 SHA 的 GitHub 保存中完成；遇到版本冲突时提示先同步，不覆盖对方更改。双方应同时升级到 V4；旧客户端无法显示 V4 习惯和积分。

LoveDiary 的解锁是双方信任基础上的应用内阅读规则。沿用原项目的共享私有仓库架构，日记正文随资料同步，持有仓库访问权限的人仍可直接读取数据；本版没有额外加密或服务端身份隔离。

本地体验数据和私有仓库数据仍分别保存。未连接私有仓库时，操作只保存在当前浏览器。

## 验证

运行 `npm test` 检查积分、习惯结算、确认流程、日记阅读规则、GitHub 保存冲突以及原有功能。运行 `npm run build` 生成发布目录 `dist/`。新增模块已加入构建、开发服务器和 Service Worker 缓存清单。
